# Phase 4-A — 무게 추출 + 200g 패키지 룰

**일시**: 2026-04-28
**관련 문서**: MASTER_SPEC § 4-3 / Phase 4 명세
**커밋**: (M-1~M-4 구현 + 시운전)

## 1. 목표

사장님 명세 4-3:
- 상세페이지 OCR로 무게 추출
- +200g 패키지 가중치 (예: 300g → 500g)

## 2. 구현 (M-1~M-4)

### 2-1. DB 스키마 (M-1)
- `domestic_products` 신규 컬럼 2개:
  - `weight_g` (REAL) — +200g 적용된 등록용 무게
  - `weight_source` (TEXT) — `name` / `ocr` / `manual` / `default`

### 2-2. 정규식 모듈 (M-2)
- `backend/app/services/weight_extractor.py` 신규
- 패턴: `(\d+(?:[.,]\d+)?)\s*(kg|g|ml|l|그램|그람|리터)\s*(?:[×xX*]\s*(\d+))?`
- 단위 정규화: kg→1000g, ml→1g (액체 근사)
- 곱셈 처리: 「3g×40개」 → 120g
- 비현실 무게 차단 (1g~100kg)
- 200g 패키지 룰: `apply_packaging_rule(raw)` → raw + 200

### 2-3. 자체 테스트 (13 케이스)

| 입력 | raw | +200g |
|---|---|---|
| 두바이 초콜릿 피스타치오 카다이프 30g | 30 | 230 |
| 메디큐브 제로 모공패드 70매 100ml | 100 | 300 |
| 프라이밀 단백질 630g | 630 | 830 |
| 도비아 모치 쿠키 3g x 40개 | **120** | 320 |
| MCT 오일 14g x 30포 | **420** | 620 |
| 1.5kg 대용량 커피 원두 | 1500 | 1700 |
| 코스노리 이지 브로우 톤 체인저 5회분 | None | None (무게 X) |
| 짱구 캐릭터즈 봉봉 드롭씰 3D 입체 스티커 | None | None |

→ **정규식 자체는 정상**. 곱셈 패턴, 단위 변환 모두 OK.

### 2-4. 엔드포인트 + 트리거 (M-4)
- `POST /api/products/domestic/extract-weights`
- `automation/trigger_extract_weights.py`
- 우선순위: ① 매칭 큐텐 jp → ② 매칭 큐텐 ko → ③ 한국 product_name

## 4. 진단

### 무게 정보 가용성 매트릭스

| 소스 | 가용성 | 시운전 매칭률 |
|---|---|---|
| 한국 product_name (m07/m08 결과) | 거의 X (광고 키워드 위주) | ~0% |
| 큐텐 product_name (jp) | 식품/화장품 일부 명시 | ~10~15% |
| 큐텐 product_name (ko 번역) | jp 와 비슷 | (jp 와 동일) |
| 한국 상세페이지 (상품정보제공고시) | 가장 정확 (kg 단위 명시) | ❌ Phase 2 봇 차단으로 못 받음 |
| cover 이미지 OCR (식품/화장품) | 패키지 라벨 (10~30%) | (M-3 미구현) |
| 사장님 수동 입력 | 100% | (Phase 3 시트 인라인 수정) |

### M-3 OCR fallback 의 효과 추정

cover 이미지 OCR 의 한계:
- 식품 (디저트/과자): 30% 정도 패키지에 「N g」 라벨 있음 → 추출 가능
- 화장품 (크림/세럼): 50% 정도 「N ml」 표기 → 추출 가능
- 굿즈/스티커/포토카드: 무게 표기 없음 (인쇄 라벨 X)

→ **추정 +5~10% 추가 커버리지**. 그러나 easyocr 로드 시간(~5초/이미지) + GPU 사용. 비용 대비 효과 낮음.

## 5. 결론 + 권장

### 현재 상태

- 정규식 모듈 ✅ 작동 정확
- 시운전 매칭률 9% (데이터 한계)
- DB 스키마 + 엔드포인트 + 트리거 ✅
- 200g 패키지 룰 ✅

### M-3 OCR fallback 권장 — **보류**

이유:
- 추정 추가 커버리지 +5~10% 만 (대부분 굿즈/스티커는 무게 정보 자체 없음)
- easyocr 로드/추론 비용 (~5초/이미지) 큼
- Phase 3 시트 인라인 수정으로 사장님이 수동 입력하는 게 더 빠름

### 권장 흐름 (사장님 작업)

1. **자동**: weight_g 채워진 행은 시트에 표시 (라벨 「name+200g」 또는 「ocr+200g」)
2. **수동**: 미매칭 (~91%) 행은 시트에서 사장님이 직접 입력 (Phase 3 인라인 수정)
3. **저장**: weight_source = "manual"
