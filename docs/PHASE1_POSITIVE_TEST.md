## 7. 임계값 튜닝 제안 (시뮬레이션 표 기반)

### 임계값 시뮬레이션 (현재 100 쌍)

| text ≥ | image ≥ | accepted |
|---|---|---|
| 0.05 | 0.70 | 24 |
| **0.10** | **0.70** | **20** |
| 0.12 | 0.70 | 17 |
| 0.15 | 0.70 | 4 |
| 0.20 | 0.70 | 1 |
| 0.30 (현재) | 0.70 | **0** |
| 0.10 | 0.85 | 7 |

### 권장 (단기)

```
TEXT_MATCH_THRESHOLD=0.10       (0.30 → 0.10)
IMAGE_MATCH_THRESHOLD=0.70      (변경 없음)
```

근거:
- **0.30 → 0% accept (코스노리 정상 매칭 모두 false negative)**
- **0.10 → 20건 accept (정상 매칭 17~18건 + IVE 굿즈 false positive 1~2건)**
- **0.85 + 0.10 → 7건만 accept (가장 보수적)** — 정상 매칭 100% 유지하면서 false positive 차단 가능

→ **첫 단계**는 `text>=0.10 AND image>=0.70` 으로 완화, 정상 매칭 살리고 false positive 1~2건은 사장님 검수 필터로.
→ **두 번째 단계**는 번역 결함 2개(브랜드명 누락 / JSON 파싱) 해결 후 임계값 0.20 정도로 다시 올림.

### 권장 (중기 — 본질 처방)

1. **번역 프롬프트 보강**: 「입력 jp 의 첫 어절(브랜드명) 은 ko 결과에 반드시 포함」 명시.
2. **text_match 알고리즘 보강**: 큐텐의 `search_keyword(kr)` 토큰을 큐텐 ko 쪽에 합쳐서 자카드 계산. 즉 brand 토큰 누락 영향 회피.
3. **번역 파싱 안전화**: JSON 파싱 실패 시 raw 첫 줄 폴백 제거 → None 반환.
