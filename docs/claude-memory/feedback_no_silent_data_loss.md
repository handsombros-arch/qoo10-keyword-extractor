데이터 동기화/캐시/저장 로직에서 **한쪽을 다른 쪽으로 일방 덮어쓰기(overwrite) 절대 금지.** 항상 dedup 키 기준 **합집합(union)** 으로 병합해 어느 저장소에 있던 데이터든 보존할 것. 데이터가 줄어드는 방향의 동작에는 반드시 사용자 경고/확인을 띄울 것.

**Why:** 2026-06-04 seller-erp ad-analysis 사고. 광고 데이터가 "말도 없이" 전부 사라짐. 원인 = 페이지 로드 시 백그라운드 DB fetch 가 로컬 IndexedDB 캐시를 통째로 덮어씀(`page.tsx` 로드 effect). 업로드는 기본 IDB 에만 저장되고 DB 백업은 수동 버튼 + 부분 실패 허용이라, DB 엔 항상 부분집합만 존재 → 새로고침 한 번에 로컬 풀 데이터가 DB 부분집합으로 교체됨. 5/3 정비 때 있던 union + 경고 배너 보호장치가 단순화 과정에서 회귀(regression)로 제거된 것. 사용자가 "매우 중요하고 근본적으로 위험한 사안"이라 강조.

## 설계 단계 근본 원인 (표면 버그 아니라 구조 문제)
1. **이중 저장소 + master 미지정.** 데이터가 IndexedDB(로컬)와 DB(서버) 두 곳에 사는데 "다르면 누가 이긴다"가 미정. 임의로 "DB가 이긴다" 골랐는데 DB가 더 불완전한 사본이었음.
2. **쓰기 권위 ≠ 읽기 권위 (비대칭).** 업로드는 IDB에만 쓰고, 새로고침은 DB로 IDB를 덮어씀 → 내가 쓰는 곳과 이기는 곳이 반대 → 반드시 갈라지고 덮어쓰기가 데이터를 죽임. **가장 깊은 결함.**
3. **append-only 데이터에 replace 의미론 적용 (범주 오류).** 광고 raw 는 안정적 키로 dedup 되는 이벤트 로그 → 유일하게 옳은 sync 는 union. 그런데 "캐시를 최신으로 교체"라는 가변 문서 사고로 모델링.
4. **데이터 감소 연산에 가드·백업·undo 전무.** 제자리 덮어쓰기 + 스냅샷/tombstone/"행 줄면 의심" 가드 모두 없음.
5. **쓰기 경로 조용한 부분 실패.** 수동 백업이 청크 일부 실패를 OK 로 넘겨 DB 가 조용히 부분집합화 → 4번 덮어쓰기가 무기화.
6. **불변식·관측 없음.** "명시적 삭제 없이 개수 안 줄어든다" invariant 없고, 행 수 급감 잡는 로그/경보 없음.
7. **안전장치 테스트 없이 회귀.** 5/3 의 union+경고배너가 "단순화" 중 사라짐. 안전 속성을 지키는 테스트 없으면 반드시 회귀.

**한 문장:** 캐시와 원천이 갈라질 수 있는 이중 저장소에서, append-only(union)여야 할 데이터에 replace 를 적용했고, 데이터 감소를 막는 가드도·지키는 테스트도 없었다.

## How to apply (재발 방지 원칙)
1. **단일 master 정하기.** DB master 면 IDB 는 순수 read-through 캐시(쓰기 전용 저장소 금지). 쓰기는 항상 master 로 먼저.
2. **데이터 본질 명시.** append-only 면 sync 는 항상 union, 절대 replace 금지. union 키 = 영속화 PK 와 글자까지 동일(idempotent → 중복 0). ad_raw_rows 키: `날짜|키워드|광고전환매출발생 옵션ID|광고 노출 지면` (route.ts PK == page.tsx dedupKey).
3. **데이터 감소 = 명시적 사용자 의도 + 확인 필수.** 백그라운드/자동 경로에선 절대 줄이지 않음.
4. **쓰기에 조용한 부분 성공 금지.** 완료 확인하거나 크게 실패하거나.
5. **파괴 전 백업.** 되돌릴 수 없는 연산은 스냅샷 먼저.
6. **안전 속성은 테스트/불변식으로 못박기.** 안 그러면 단순화 때 또 사라짐.
- 미백업/미동기 데이터가 로컬에만 있으면 가시화(경고 배너)해서 silent 손실 방지.
- 관련 위험: [[project_lv10_reset]] 의 save_keywords delete-before-insert. 같은 부류 — delete 먼저 하고 insert 실패 시 데이터 증발.

복구 불가 교훈: 사라진 데이터는 다른 기기 IDB / Storage 원본 백업 / 원본 파일이 없으면 못 살림. 예방이 유일.
